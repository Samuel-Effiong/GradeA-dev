## What was wrong
Found by Verifier 1's x6 (green on f12f12d0): `POST /auth/google-auth` on an EXISTING, never-verified account stamps `email_verified_at`, activates it if inactive and signs it in, whoever it is, so the holder of a never-verified super admin's mailbox and a Google account for that address was signed in as it. The road list (ROADS.md) found two more mailbox-only roads that only needed one call of the same helper: `POST /auth/register/school-admin` (a pending SCHOOL_ADMIN row that the Django admin gave is_staff or is_superuser) and `enroll_student_by_email` (a STUDENT-typed row carrying is_staff). The Senior Manager ruled all three in, each as one call of the helper with one test.

## The change
- `users/admin_power.py` (new): the PRINCIPLE as its docstring and `holds_admin_power(user)` (moved out of views.py; views keeps the name `_holds_admin_power` by import, so H-164's and H-202's code is unchanged).
- Google existing account: `if user.email_verified_at is None and _holds_admin_power(user): raise ParseError(GOOGLE_SIGN_IN_FAILED)`, placed after the verified-and-deactivated carve-out and before anything is written. `GOOGLE_SIGN_IN_FAILED` is the existing fallback text of a failed Google token exchange ("Google sign-in failed. Please try again."), now one constant used by both.
- Invitation road: `if not user or _holds_admin_power(user): raise ParseError("Invalid or expired activation token.")` (one line, the answer for a wrong token).
- Add-by-email: `check_existing_account_may_join` (the single gate of single add, bulk import and direct add) refuses `holds_admin_power(student)` with the existing not-a-student error.
- Today's behaviour kept (control): an ordinary existing, never-verified account signing in with Google is stamped verified, activated if inactive (with an unusable password) and signed in; a verified-and-deactivated account is refused with 401 (the carve-out).
- **No attempt budget or lock on these roads** (read: only `/auth/verify` has `reserve_verify_attempt`/`lock_verify_address`; Google and the invitation road have throttles only; add-by-email none), so the lock gap of H-164/H-202 has no analogue here.
