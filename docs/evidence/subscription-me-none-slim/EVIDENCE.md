# Evidence — slim the NONE response of GET /subscription/me

Branch `task/subscription-me-none-slim`, off beta `4b902fc`. Author: Integration & Release Engineer (grade-automator-plus-0b). Founder-requested.

## 1. Change

- `billing/views.py` `_none_subscription_response()` returned ~35 null/false/0 fields mirroring `MySubscriptionSerializer`. It now returns exactly:
  `{"status": "NONE", "message": "You don't have a subscription yet."}`
- The `@extend_schema` example "No subscription ever existed" shows the same body.
- ACTIVE and EXPIRED are unchanged on all three tracks (INDIVIDUAL, LICENSE_TEACHER, LICENSE_ADMIN).
- Founder decision (via SM): `subscription_source` is **not** added to the individual response. The scope is only the NONE body.

## 2. Tests

- `billing/tests/test_subscription_me_status.py`: the old "NONE matches the ACTIVE shape" test is replaced by `test_none_response_is_exactly_status_and_message_no_other_fields`, which pins the exact key set `{status, message}`. The precedence tests (lapsed history on any track gives EXPIRED, not NONE; an admin-only allocation gives NONE) are kept unchanged.
- `billing/tests/test_subscription_me_payload_samples.py` (new): one test per state. Each builds the state, calls the endpoint, and asserts the HTTP code, `success`, and `data.status` on the **rendered bytes**.
- Targeted run, both modules: **31 tests OK**.

## 3. Mutation check

Restored the old 35-field dict in `_none_subscription_response()` and ran `NoneStatusTests`: **1 failure** (the key-set test; it lists the 31 extra keys and the missing `message`). The status-only NONE test still passes, which is expected, since it only checks `status`. Real implementation restored afterwards: 22/22 OK.

## 4. Real payloads, exactly as the frontend receives them

Generated by the endpoint under test, not hand-written: `SUBSCRIPTION_ME_SAMPLES_DIR=<this dir>/payloads python manage.py test billing.tests.test_subscription_me_payload_samples`. Every response goes through `users.renderers.APIJSONRenderer`, so the frontend gets an **envelope** `{"success", "message", "data"}`; the subscription fields are inside `data`.

| State | File | HTTP | `data.status` | `data` keys |
|---|---|---|---|---|
| INDIVIDUAL active | `payloads/individual_active.json` | 200 | ACTIVE | 34 |
| INDIVIDUAL expired | `payloads/individual_expired.json` | 200 | EXPIRED | 34 |
| INDIVIDUAL none | `payloads/individual_none.json` | 200 | NONE | **2** |
| LICENSE_TEACHER active | `payloads/license_teacher_active.json` | 200 | ACTIVE | 18 |
| LICENSE_TEACHER expired, own allocation deactivated | `payloads/license_teacher_expired_allocation_deactivated.json` | 200 | EXPIRED (`is_license_active: true`) | 18 |
| LICENSE_TEACHER expired, parent license lapsed | `payloads/license_teacher_expired_parent_license_lapsed.json` | 200 | EXPIRED (`is_license_active: false`) | 18 |
| LICENSE_ADMIN active | `payloads/license_admin_active.json` | 200 | ACTIVE | 20 |
| LICENSE_ADMIN expired | `payloads/license_admin_expired.json` | 200 | EXPIRED | 20 |
| Student caller | `payloads/student_forbidden.json` | 403 | — (`success: false`) | — |

The NONE response in full:

```json
{
  "success": true,
  "message": "You don't have a subscription yet.",
  "data": {"status": "NONE", "message": "You don't have a subscription yet."}
}
```

**Observation for the founder/frontend:** the renderer lifts `data.message` into the envelope `message`, so the NONE text appears twice (envelope and `data`). ACTIVE/EXPIRED envelopes say "Request Successful". This is existing renderer behaviour, not changed here.

Sample data uses test fixtures only (`@example.com` addresses, random UUIDs, run-time timestamps). No real user data.
